Two skies. One honest pipeline.

HuellaX integrates MoveScope — our SQL-backed, multi-epoch SPHEREx motion laboratory — with AstroNova/HUELLA X, the NASA Space Apps 2026 prototype preserved as a legacy static demo. One repository, two eras, one boundary: we report candidates, not discoveries.

All three services bind to 127.0.0.1 by default. The legacy page is a static demo: generate its synthetic fields first, then serve the repository root over HTTP. Neither is a public service.

The integration contract

What is primary, what is legacy, what never changes

The merge is deliberately asymmetric. The live science and data path is MoveScope plus the SQL catalog. AstroNova is kept because its interaction and contract ideas are valuable — not because its demo data is evidence.

Source of truth

SQL is the primary data source

Targets, epochs, coverage and cutout indexes live in the SQLite catalog and immutable blob store (8797). MoveScope resolves arbitrary coordinates through the /api/v1/epochs contract at runtime.

Local JSON under 系统/app/data/ is an explicit offline fallback for preset targets — never a second source of truth.

Preserved upstream

AstroNova is legacy / demo

astro/ preserves the AstroNova/HUELLA X static site and offline pipeline at upstream commit 1253925. It is a UI and contract reference.

Its shipped fields are synthetic. They are not observations, not validation, and not the evidence behind any MoveScope result.

Scientific boundary

Candidates, not discoveries

Every detection, track and catalog status is a candidate. The product carries discovery_claim: false and never converts “no catalog match” into “new star” or “new planet”.

No Planet X confirmation. No claim of a discovery. Unavailable or partial catalog results are reported as such, never as “not found”.

Architecture

One data plane, one measurement plane, one experience plane

The SQL catalog owns what was observed. MoveScope owns what the measurements mean. The view tool supplies sky context. The catalog service answers “is this known?” — it does not classify.

8790

MoveScope app

No-build browser UI plus /api/analyze, cascade, tracks and identify. Owns photometry, motion models and readiness L0–L3.

8797

SQL catalog

SQLite metadata plus content-addressed blobs. Serves /api/v1/epochs and /api/v1/coverage; owns the single epoch truth.

8830

Sky View

Optional 3D sky and Earth context. Sends one full-precision handoff URL with ra, dec, fov, t0, t1.

8799

Catalog service (B)

Gaia DR3 field cache with 2MASS/WISE crossmatches. Returns known, ambiguous, uncatalogued_candidate or unavailable; read-only, no science classification.

8798

Coverage service (C)

Any-field discovery, true header footprints and allowlisted S3/IRSA cutout fetch. Read-only catalog; writes only its own sidecar. Never invents SIM data.
